A dialog often needs more than a title and two buttons: a field to fill, a list to pick from, a name to type before a delete. Write that content as plain HTML. Inside a dialog with the default CSS, `h1` to `h3`, `p`, `label`, `input`, `textarea`, `select` and `button` get the default look with no class names. A CSS reset such as Tailwind preflight does not remove it, and any class you add wins over it.

Every example on this page is in the [playground](/playground), where you can switch how it is written: `openDialog`, `<Dialog>`, `confirm` with `content`, or 3.0 `customUI`.

## customUI from 3.0

`customUI` keeps its 3.0 look by default. Add `skin: true` and your content sits in the new dialog body with the same default look. `configureDialogs({ confirmAlert: { skin: true } })` turns it on for every `confirmAlert` call.

## Which API to use

| You want | Use |
| --- | --- |
| A value back from your content | `openDialog<R>({ render })` |
| Content that reads your component's state | `<Dialog open onOpenChange>` |
| A confirm, alert or prompt with something extra under the message | `confirm({ content })`, `alert({ content })`, `prompt({ content })` |
| The 3.0 API | `confirmAlert({ skin: true, customUI })` |

To style the content yourself, add classes, use `data-slot` attributes (see [Styling](/docs/styling#your-own-content)), or turn the default look off with `unstyled: true`.
