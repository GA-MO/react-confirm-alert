## customUI from 3.0

`customUI` keeps its 3.0 look. Add `skin: true` and your content gets the new look. `configureDialogs({ confirmAlert: { skin: true } })` turns it on for every call.

## Reference

### Which API to use

<div className="var-table api-table">

| Use | When you want |
| --- | --- |
| `openDialog<R>({ render })` | A value back from your content. |
| `<Dialog open onOpenChange>` | Content that reads your component's state. |
| `confirm({ content })` | A confirm with something extra under the message. `alert` and `prompt` take `content` too. |
| `confirmAlert({ skin, customUI })` | The 3.0 API with the new look. |

</div>

### Elements with the default look

`h1` to `h3`, `p`, `label`, `input`, `textarea`, `select` and `button`. The rules sit under `:where()`, so any class you add wins. Tailwind v4 preflight does not remove them.

To style the content yourself, add classes, mark it up with [`data-slot`](/docs/styling#your-own-content), or drop the default look with `unstyled: true`.
