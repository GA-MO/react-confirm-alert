Most looks take one to three CSS variables. Press a button to open the dialog, then copy the code under its example. The examples go from the smallest change to the largest.

<StylingGallery />

Each example puts its variables on a class that it passes to `classNames.dialog`, so only that dialog changes. To change every dialog in your app, put the same variables on `:root` and leave `classNames` out:

```css
:root {
  --rca-button-bg: #4f46e5;
}
```

### Dark mode

Dark colours are off until you turn them on. Put `class="dark"` or `data-theme="dark"` on an ancestor of the dialog, usually `<html>`:

```html
<html class="dark">
```

The library does not follow the OS setting by itself, so it cannot disagree with your app's own theme switch. To follow the OS, set the class from `prefers-color-scheme` in your theme code. To change the dark colours, set `--rca-*` variables under your dark selector.

## Slots

`classNames` takes a class per slot: `dialog`, `panel`, `body`, `title`, `message`, `actions`, `button`, `field`, `label`, `input`, `error`. Classes add up in this order: the 3.0 class (unless `unstyled`), `configureDialogs`, the call, then a 3.0 button `className`.

## Your own content

Inside a dialog with the default look, plain `h1` to `h3`, `p`, `label`, `input`, `textarea`, `select` and `button` are styled with no class names. Those rules sit under `:where()`, so any class you add wins over them, and they still beat a reset such as Tailwind preflight. `DialogLayout` adds the body and the button row for you. To mark up the parts by hand, use the same markup as `prompt`:

| Element | Markup |
| --- | --- |
| Body | `className="react-confirm-alert-body"` |
| Heading (`h1`, `h2` or `h3`) | `data-slot="title"` |
| Label and control wrapper | `data-slot="field"` |
| Label | `data-slot="label"` |
| `input`, `textarea` or `select` | `data-slot="input"` |
| Error text | `data-slot="error"` |
| Button row | `className="react-confirm-alert-button-group"` and `data-slot="actions"` |
| Main button | `data-variant="primary"` or `data-variant="danger"` |

A `data-slot="input"` control fills the width of the dialog and has a border. A `textarea` is at least 80px tall and resizes vertically.

```tsx
<Dialog
  open={open}
  onOpenChange={setOpen}
  aria-labelledby="note-title"
>
  <div className="react-confirm-alert-body">
    <h1 id="note-title" data-slot="title">Edit note</h1>
    <div data-slot="field">
      <label htmlFor="note" data-slot="label">Note</label>
      <textarea
        id="note"
        data-slot="input"
        value={note}
        onChange={(e) => setNote(e.target.value)}
      />
    </div>
    <div
      className="react-confirm-alert-button-group"
      data-slot="actions"
    >
      <button data-variant="primary" onClick={() => setOpen(false)}>
        Done
      </button>
    </div>
  </div>
</Dialog>
```

A `data-slot` rule is more specific than the plain element rules, so use it when your own CSS would otherwise win.

The plain element rules are built to beat Tailwind v4 preflight. Tailwind v3 preflight and `@tailwindcss/forms` use attribute selectors such as `[type='button']`, which win over them: there, a plain `<button type="button">` loses its background. Use `data-slot` and `data-variant`, `DialogLayout`, or classes in those setups.

## Data attributes

The frame has `data-rca`, `data-state` (`open` or `closing`), `data-kind`, `data-tone`, `data-depth`, `data-topmost` and, while a button waits, `data-busy`. Every slot has `data-slot`; buttons have `data-variant`.

## Unstyled

`unstyled: true` drops every `react-confirm-alert-*` class and inline style. Behavior stays: focus, Escape, outside clicks, waiting for exit animations. With `unstyled`, lock scroll in your own CSS.

## Motion

Closing waits for animations and transitions on the frame, its `::backdrop` and the panel, so an exit transition on `[data-state='closing']` plays out. `prefers-reduced-motion: reduce` turns the default fade-in off.

## Reference

Every CSS variable the default CSS reads. The Default column is what `confirm`, `alert`, `prompt`, `openDialog` and `<Dialog>` use. `confirmAlert` without `skin` keeps its 3.0 look and reads the values in the 3.0 column. A dash means the 3.0 look does not read that variable.
